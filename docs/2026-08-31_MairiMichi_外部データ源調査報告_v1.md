**実装上の注意（2点とも重要）**

1. **`name:ja` が 6% と低いのは欠損ではない。** 日本のマッパーは `name` に直接日本語を入れる。**`name` を主キーにし、`name:ja` は当てにしない。**
2. **`religion=shinto` 全体（53,338）と `amenity` 併用（40,981）の差 約12,000件は鳥居・史跡類**（`man_made=torii` 4,057件など）。**必ず `amenity=place_of_worship` で絞る。**

**取れないもの**: 祭神・宗派・本尊（`denomination` は上位60タグ外＝ごく少数）／公式サイトURL（実質皆無）／宗教法人との対応

**ライセンス・帰属義務**: **ODbL 1.0**
- Webアプリでの必須表記: **「© OpenStreetMap contributors」**（"OpenStreetMap" を `openstreetmap.org/copyright` へリンクでも可）
- 地図の**隅**に表示。パン/クリック/ズーム時、5秒経過時、ユーザーが×を押した時に折りたたみ可。折りたたむ場合もボタン/メニューから到達可能にすること
- **シェアアライク**: 単に地図表示する Produced Work なら義務なし。ただし**OSMからの実質的な抽出は Derivative Database とみなされ ODbL 公開義務が生じうる**。「全国の神社リストをDBにして配布」はこれに該当する可能性が高い

**⚠️ 実務上の警告**: 本調査中、フェアユース範囲内の十数回のクエリで **overpass-api.de から IP レベルで遮断された**（以後 `/api/status` すら応答なし）。**プロダクションでは Overpass を実行時に叩かず、Geofabrik の日本 PBF を自前で ETL すること。**

[知恩院]       [[法然]]上人像（御影堂）<br />[[阿弥陀如来]]（阿弥陀堂）
```

**実装上の最重要知見**: **パイプリンクは「表示名」ではなく「リンク先記事名」を正規化キーに使う。** `[[イチキシマヒメ|市杵島姫命]]` `[[市寸島比売命|狭依姫命]]` はどちらもリンク先が正規名に寄っており、表示名の揺れ（41.2%）を無料で吸収できる。一方 **23.8%（93/391）はリンクゼロの素テキスト**で、別名辞書によるあいまい一致が必須。

**取れないもの**
- **`相殿` / `配神` が主祭神と区別なく同一フィールドに並ぶ。infobox から「主祭神」と「相殿神」を機械的に分離できない。**
- 一部記事は `{{wikidata|...|P825|...}}` で Wikidata から祭神を引いており（例: 伊勢神明社(静岡市)）、素朴な正規表現では取れない
- **座標の記法が3パターンある**: `{{coord}}`（浅草寺）／度分秒個別パラメータ（明治神宮）／`{{WikidataCoord}}`（出雲大社。**Wikidata へ委譲されている**）。全てに対応が必要

**記事数の目安**（`list=search` の `insource` 全文検索ヒット数。誤ヒットを含む概算）: `insource:"{{神社"` 約 **55,835** ／ `insource:"{{日本の寺院"` 約 **9,038**。正確な transclusion 数は `list=embeddedin` が HTTP 429 で中断し**未確認**。

**API とレート制限**

```
GET https://ja.wikipedia.org/w/api.php
  ?action=query&prop=revisions&rvprop=content&rvslots=main
  &format=json&formatversion=2&titles=A|B|C          # 最大50タイトル
GET https://ja.wikipedia.org/w/api.php?action=parse&page=X&prop=parsetree&format=json
```

- **2026年3〜4月に Wikimedia が新しいグローバルAPIレート制限を導入済み**（匿名に低い上限、認証済みに高い上限の段階適用）。**公式アナウンスに数値の明示がなく、正確な req/sec は未確認**
- **実測**: 40タイトル×10バッチを連続実行 → **半数以上が HTTP 429**。**各リクエスト間 6秒スリープ＋リトライで400件を完走**
- **User-Agent ポリシー**: 連絡先を含む固有UA が必須。汎用UAやライブラリ既定UAはレート制限対象
- 上限緩和の正規ルート: bot フラグ / Toolforge・WMCS 上での実行 / Wikimedia Enterprise API

**→ 本番のデータ構築は API ではなくダンプで行う。** `https://dumps.wikimedia.org/jawiki/latest/jawiki-latest-pages-articles.xml.bz2`（**4.71 GB**、Last-Modified 2026-08-04、HTTP 200 確認済み）

**ライセンス**: **CC BY-SA 4.0**。→ **infobox から抽出した祭神テキストを再配布するなら BY-SA の帰属・継承義務が及ぶ可能性がある。** 実務上の回避策は「どの記事にリンクしているか」という**事実**だけを抜き、自前の御利益マスタと突き合わせて自社DBを構築すること。**法的判断は本調査の範囲外・未確認。** 安全を最優先するなら Wikidata(CC0) を主軸にする。

### 1.4 国土数値情報（社寺系）— 【商用なら不採用】

**神社仏閣を面的に網羅するデータセットは存在しない。** P02〜P36 を通覧して該当なし。関連する3つはいずれも「非商用」。

| データ | 内容 | 判定 |
|---|---|---|
| **P12 観光資源** | 「社寺」が観光資源分類の1カテゴリとして含まれる。属性: 観光資源ID/名/都道府県コード/行政区域コード/種別名称/所在地住所/観光資源分類コード。基準日 2014-09-30 | **不可（非商用）**。しかも**全国「B級以上」約2,000件のみ**で網羅性は皆無に近い |
| **P27 文化施設** | 美術館・資料館・記念館・博物館・科学館・図書館・水族館・動植物園・スポーツ施設 | **社寺を含まない**（当初想定と異なる） |
| **P32 都道府県指定文化財** | 座標あり。文化財ID・分類コード大小・名称・住所・指定年月日。2014-01-31時点 | **不可（非商用）** |
| P01 文化財 | 昭和50(1975)年。属性は文化財番号と区分のみ | 51年前。実用性なし |

**Web API は稼働していない。** 旧 `nlftp.mlit.go.jp/ksj/api/1.0b/index.php/app/getKSJURL.xml` は **404**。現行APIの有無は未確認（ZIP直ダウンロードのみ確認）。

**ライセンス**: 全体の既定は **PDL 1.0（公共データ利用規約 第1.0版）**（CC-BY ではない）。ただし**データセット単位で上書き**され、上記3つは「非商用」明記。帰属: `出典：国土交通省国土数値情報ダウンロードサイト（URL）`。加工時はその旨を併記し、国が作成したかのような態様での公表は禁止。

### 1.5 文化庁 国指定文化財等データベース — 【限定採用】

- **公開APIも一括DLも無い。** サイト内に「検索用APIの共通化」(2018年実施)への言及はあるが、公開エンドポイントもドキュメントも見つからず**未確認**

## 4. 経路探索API

### 4.1 OSRM 公開デモ — 【徒歩には使えない・実測で確定】

**プロファイルが車のみ。** URLのプロファイル部分は**完全に無視**されており、常に車プロファイルが返る。

```
/route/v1/foot/...    → duration 547.8s, distance 3906m
/route/v1/driving/... → duration 547.8s, distance 3906m   ← 完全一致
/route/v1/zzzz/...    → HTTP 200, 同一結果              ← 存在しないプロファイルでも200
table: [[0, 3906], [4595.9, 0]]  ← 非対称＝一方通行を効かせている＝車
```

規約（`https://github.com/Project-OSRM/osrm-backend/wiki/Api-usage-policy`）: 「Excessive use is not allowed. If your requests are impacting the service stability, we will block you.」／有効なUser-Agent必須／ODbL表示必須／**予告なくアクセス遮断あり**／商用サービスからの利用は特に不可。

### 4.2 Valhalla — 【採用・徒歩の本命】

公開インスタンス（`https://valhalla1.openstreetmap.de` に POST）は実在し、**徒歩プロファイルが正しく機能する**。日本のデータ品質も良好。

実測（京都駅→清水寺）:

| costing | 距離 | 所要 |
|---|---|---|
| `pedestrian` | **3.481 km** | **2,684 s（44.7分）** |
| `auto` | 4.123 km | 785 s（13.1分） |

車と徒歩で経路・距離・時間が明確に分かれており、歩行者専用路を使っている。

エンドポイント（全て HTTP 200 確認）:
- `/route` — 1対1経路
- **`/sources_to_targets`** — 距離行列（1リクエストで多対多。1×3で実測成功）
- `/isochrone` — 到達圏ポリゴン（徒歩15分圏を実測成功）

- 料金: 無料・キー不要。ただし公式READMEに「Usage of the demo server follows the usual fair-usage policy as OSRM & Nominatim demo servers (somewhat enforced by rate limits)」。**具体的なレート上限値は未確認**。エンドユーザ向けアプリは `X-Client-Id` ヘッダ推奨。**大量バッチには使わないこと**
- **セルフホスト可、MIT ライセンス**（最も制約が緩い）

### 4.7 結論: 徒歩の実距離を安価に大量計算する現実的手段

### 5.1 標高API（getelevation.php）— 【単発用途のみ】

```

### 5.2 標高タイル（DEM）— 【採用・これが正解】

**1リクエスト＝65,536点の標高。** タイルのデコード結果と標高APIの値が一致することを検証済み。

### 6.5.6 Google Places `user_ratings_total` — 【規約違反・不採用】

規約を原文で確認:
- **Maps Service Terms §14.3 Caching**: "Customer may temporarily cache **latitude and longitude values** from the Places API for up to **30 consecutive calendar days**…"
- **§A.3 Google ID Caching**: `place_id` は無期限キャッシュ可（例外規定）
- Places API Policies: "You must not pre-fetch, cache, or store Places API content beyond the allowed exceptions."

**30日キャッシュが明示的に認められているのは緯度経度のみ。恒久保存できるのは `place_id` だけで、`rating`／`userRatingCount` は許容例外に含まれない。**
→ **収録優先度をDBに永続保存する用途は規約違反。**

価格（第三者情報・**Google公式価格表は取得できず未検証**）: Place Details Essentials $5.00/1,000、Pro $17.00/1,000、Enterprise $20.00/1,000。`rating` 系は Enterprise ティア。数千社×定期更新なら規約・費用の両面で不適。

| OSM で `name` すら無い神社オブジェクト | — | 約33% |

**神社の9割超は Wikipedia 由来のいかなる指標でもスコア0になる。** その多くは日常的に参拝されている地域の氏神。

**対処（3層）**
1. **スコアリング層と網羅層を分離する。** スコアは収録の「順番」にのみ使い、「可否」には使わない。可否は宗教法人リスト／OSM／Wikidata の**和集合**で決める。分離しないと「記事が無い＝存在しない」が構造化される
2. **記事なし社には別系統の優先度を与える**: ①観光入込客統計に地点として掲載 ②OSM に `name` がある ③式内社・一宮・別表神社などの社格 ④**近隣人口密度**（「氏神は氏子の数だけ参拝される」＝Wikipedia に依存しない唯一の全国一様な代理指標）
3. **正月比を小規模社の救済に使う。** **廣瀬大社は絶対views 6,809（伏見稲荷の1/10）ながら正月比 1.72 で伏見稲荷 1.59 を上回る。** 記事が存在しさえすれば、正月比は規模を問わず「実際に参拝されているか」を検出する。この特性は絶対値ベースのどの指標にもない

### 6.6.3 延喜式神名帳の実データ

冒頭に総数規定がそのまま入っている: 「天神地祇惣三千一百〓二座 / 社二千八百六十一処 / 大四百九十二座 / 小二千六百〓座」

国 → 郡 → 社の階層で、各社に割注が付く:

```
羽束師坐高御産日神社／大。月次新甞。∥
乙訓坐大雷神社／名神大。月／次新甞。∥
川田神社二座
```

取れるもの: **社格（名神大/大/小）／官幣・国幣の別（案上官幣・案下官幣・国幣）／祭祀（月次・新嘗・相嘗の預かり）／座数**

**パースの注意点**
- 割注が `／…∥` の**独自記法**
- **`〓`（欠字）と `■` マーカーが散在**し、数値の一部が欠けている
- `貞コ`（おそらく「貞観」）のような文字コード変換の残骸
- **現在の比定社（論社）は含まれない**（10世紀の記載そのもの）
